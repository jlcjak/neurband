# neurband rev C firmware and BLE recorder

> **SAFETY.** The band is worn only when it runs from its battery and streams over BLE. Never
> wear it while it charges, while SWD is attached, or while any cable or grounded instrument
> touches it. The charge contacts are physically unreachable while the band is worn
> (mechanical design). The firmware adds a second line of defence: while TP4054 CHRG
> (CHG_N, P0.17) is low, it powers the ADS1298 down (PWDN/RESET low), refuses `start`,
> and stops a running stream at once. This interlock is **not isolation**: the electrodes
> stay galvanically connected to the board, and therefore to a charger cable. The 100 kΩ
> bias limiter is not mains isolation either (docs/science/signal_chain.md section 6).

Code: `firmware_c/` (Zephyr / nRF Connect SDK) and `host/neurband_ble.py` (Python + bleak).
Hardware source of truth: `boards/neurband_c/gen_c_sch.py`. ADS1298 register choices cite
TI SBAS459K (`docs/datasheets/ads1298.txt`) section numbers in `firmware_c/src/ads1298.c`.

**Status:** the firmware has **not been linked or run on hardware**. It configures (Kconfig and
devicetree) and every source compiles with 0 errors and 0 warnings against upstream Zephyr
v4.4.2 (`nrf52dk/nrf52832`, open-source LL controller), using host clang in a throwaway
checkout. No ARM linker was available, so it was never linked: flash size, RAM fit
(static estimate ~60 of 64 KB) and NCS/SoftDevice Controller builds are unverified. The DSP
(`dsp.c`) was compiled on the PC and matches a numpy reference. The host parser has unit tests.

## Build and flash

Board target: the stock **`nrf52dk/nrf52832`** definition (same SoC, nRF52832-QFAA with a
32 MHz crystal) plus `firmware_c/boards/nrf52dk_nrf52832.overlay`, which Zephyr applies
automatically. The overlay:

- remaps SPIM2 to the ADS pins and makes it `nordic,nrf-spim` (EasyDMA);
- adds the `ads1298` and `lsm6dsl` nodes and a `zephyr,user` node (LED, button, CHG_N,
  VBAT ADC);
- deletes the DK LEDs, buttons and PWM LED (they sit on our pins) and disables UART0, which
  is on P0.06/P0.08, now SPI. Logging goes over SEGGER RTT through SWD.
- **forces the regulator to LDO mode.** The DK enables DC/DC, but rev C has no DCC inductor.
  On Zephyr ≥ 4.0 the overlay does this (`&reg`). On Zephyr 3.7 / NCS 2.x, `CMakeLists.txt`
  adds `zephyr37.conf` (`CONFIG_BOARD_ENABLE_DCDC=n`, PAN 58 SPIM permit). It decides from
  `$ZEPHYR_BASE/VERSION`, which west exports. Without west, add
  `-DEXTRA_CONF_FILE=zephyr37.conf` yourself on 3.7.
- HFXO: the nRF52832 has no internal HFXO load capacitors. Y1 (CL 8 pF) has 12 pF external
  caps, so there is nothing to set; the BLE controller starts the HFXO for radio events.
  There is no 32.768 kHz crystal, so `prj.conf` selects the calibrated LFRC (±500 ppm).

```sh
# nRF Connect SDK (>= 2.7) or upstream Zephyr (>= 3.7) workspace
west build -b nrf52dk/nrf52832 path/to/neurband/firmware_c        # NCS: also picks sdc.conf
west flash                                  # J-Link / nrfjprog / nrfutil, if you have one
west flash --runner pyocd                   # any CMSIS-DAP probe
west flash --runner openocd                 # any CMSIS-DAP probe via OpenOCD
```

On NCS, `CMakeLists.txt` detects the SoftDevice Controller and adds `sdc.conf` (10 LL TX
buffers, 7.5 ms event length, event extension).

**Cheap probe (~$4-12):** a Raspberry Pi Pico (or Pico 2 / Debug Probe) running
[debugprobe](https://github.com/raspberrypi/debugprobe) is a CMSIS-DAP v2 probe. Wire GP2 → SWDCLK
pad, GP3 → SWDIO, GND → GND. Leave probe 3V3 disconnected when the band runs on its battery;
on the bench, either the battery or the probe's 3V3 powers it, never both. The NRST pad
(P0.21) is optional.

```sh
pyocd pack install nrf52832                  # once
pyocd flash -t nrf52832 build/zephyr/zephyr.hex
pyocd rtt -t nrf52832                        # log output (RTT)
openocd -f interface/cmsis-dap.cfg -c "transport select swd" -f target/nrf52.cfg \
        -c "program build/zephyr/zephyr.hex verify reset exit"
```

A fresh nRF52832 may have APPROTECT enabled. Erase it first: `pyocd erase -t nrf52832 --chip`,
or `nrf52.dap apreg 1 0x04 0x01` in OpenOCD.

The filter coefficients `src/filter_coefs.h` are generated by `python3 tools/gen_filters.py`.
The script also checks the FIR response and the float32 rounding error.

## Pin map (nRF52832 P0.xx)

| pin | net | use |
|---|---|---|
| P0.06 | ADC_CS | SPIM2 CS (GPIO, active low) |
| P0.07 / P0.08 / P0.11 | SPI_SCK / SPI_MOSI / SPI_MISO | SPIM2, mode 1. Registers 1 MHz, frames 8 MHz |
| P0.12 | ADC_DRDY | input, falling-edge interrupt |
| P0.13 | ADC_START | output, high = convert |
| P0.14 | ADC_PWDN | output to ADS PWDN **and** RESET, low = power-down (also clears registers) |
| P0.15 | LED | active low (LED from +3V3 via 1 kΩ into the pin, ~1.4 mA) |
| P0.16 | BUTTON | to GND, internal pull-up. Press = marker; hold 3 s = System OFF; wakes from System OFF |
| P0.17 | CHG_N | TP4054 CHRG (open drain, low = charging), internal pull-up. Interlock; wakes from System OFF |
| P0.02 / AIN0 | VBAT_SENSE | VBAT/2 (1 M/1 M + 100 nF), SAADC gain 1/6, 0.6 V ref, 12 bit, 4× oversampling |
| P0.03 / P0.04 | I2C_SDA / I2C_SCL | TWI0, 400 kHz, LSM6DSL at 0x6A (SA0 low, CS high); moved off P0.22/P0.23 (near-radio low-drive bank) during layout |
| P0.24 | IMU_INT | LSM6DSL INT1, rising edge (data-ready pulse) |
| P0.21 | NRST | reset pad (`gpio-as-nreset` from the DK) |
| SWDIO / SWDCLK | — | SWD pads |

All of this sits in one place: `firmware_c/boards/nrf52dk_nrf52832.overlay`. If the layout
swaps pins, only the overlay changes.

## Architecture

```
DRDY ISR ──sem──> acq thread (coop prio 2): SPI read 27 B (EasyDMA, 8 MHz, ~35 us)
                     │  frame ring (64 frames = 16 ms @ 4 kSPS), counts overruns
                     v
                  proc thread (preempt 1, FPU): status word, DC tracker, FIR/2, HP, int16,
                     │  packetizer, 1 s diagnostics, RLD sense auto-drop
IMU INT1 ISR (latches ADS sample index) ──> imu thread: I2C read 12 B ──┐
                     v                                                   v
                  packet queue (20 x 244 B, k_msgq) ──> BLE TX thread: bt_gatt_notify
control writes ──> app work queue: commands, AFE power, charger, battery, LED, System OFF
```

Each stage counts its losses. The first sample index in each packet header jumps over
anything lost: missed DRDYs, ring overflow, or packets dropped when the queue was full
(the `seq` field still advances for those). The host therefore sees every gap and never
interpolates over one.

## ADS1298 bring-up and registers

`ads_power_up()` follows 11.1 / Table 38 and 9.3.2.2:

1. PWDN/RESET high.
2. Wait 300 ms: tPOR = 2^18 tCLK = 128 ms, and VCAP1 (22 µF) > 1.1 V.
3. SDATAC (the chip wakes up in RDATAC), RESET opcode, wait 20 µs (18 tCLK), SDATAC.
4. Read the ID; expect 0x92.
5. CONFIG3 = 0xC4 (reference on, external RLDREF divider; 0xCC if the divider is not fitted), wait 300 ms for VREFP to settle.
6. Write all registers and read each one back. The mismatch count is `verr` in the status.

The AFE is powered when a central connects (unless charging), so `status` shows the ID
right away. It powers down on disconnect, on charging and before System OFF.

| reg | value | reason (datasheet section) |
|---|---|---|
| CONFIG1 | 0x83 (4 kSPS) / 0x84 (2 kSPS) | HR=1, DAISY_EN=0, CLK_EN=0 (CLK pin unused, CLKSEL high), DR (9.6.1.2) |
| CONFIG2 | 0x00, test: 0x10 | INT_TEST=1, 1 × VREF/2400, fCLK/2^21 ≈ 0.98 Hz (9.6.1.3) |
| CONFIG3 | 0xC4 | internal 2.4 V reference, RLDREF_INT=0: bias reference from the 2x1M + 1uF divider on RLDREF (keeps radio bursts out of the body bias, docs/science/simulations.md); build with -DNEURBAND_RLDREF_EXTERNAL=0 for 0xCC on boards without it (9.6.1.4) |
| LOFF | 0x00, lead-off: 0x03 | DC lead-off, 6 nA current source, 95 %/5 % comparators (9.6.1.5) |
| CH1-8SET | gain code << 4 \| mux | gain 6 default; mux 000 normal, 001 short, 101 test (9.6.1.6) |
| RLD_SENSP/N | `rld` mask, default **0x0F** (8 sensed inputs; simulated 57° phase margin with 1M‖4.7nF) | only selected channels (P+N) drive the bias loop (9.6.1.7/8), see below |
| LOFF_SENSP/N | 0x00 / 0xFF | lead-off current on all inputs only with `leadoff on` (9.6.1.9/10) |
| LOFF_FLIP | 0x00 | default polarity (9.6.1.11) |
| CONFIG4 | 0x00 / 0x02 | lead-off comparators on only with lead-off (9.6.1.17) |
| WCT1/2 | 0x00 | WCT amplifiers off (9.6.1.18/19) |

**Bias (RLD) loop.** Rev C uses 1 MΩ ∥ 4.7 nF feedback. Following signal_chain.md section 3,
the firmware does not sense all 16 inputs by default. Channels 1-4 (P and N, 8 inputs) start the loop,
and `rld <mask>` picks any set; `rld 0` holds the body at mid-supply with no feedback. With
`leadoff on`, a channel that shows lead-off is removed from the sense set within one second.
The register write happens between two frames: SDATAC, WREG×2, RDATAC, ~90 µs. A channel
rejoins after 3 clean seconds. `rld=cfg/active` in the status and `rld_active` in the diag
packets show the set in use. Lead-off flags are only valid with lead-off on. Turn it off for
clean noise recordings: the 6 nA current adds DC offset on dry contacts.

## DSP (default stream)

The default stream is **2 kSPS, int16, 0.25 µV/count**, from 4 kSPS acquisition
(signal_chain.md sections 4 and 7):

1. **DC tracker**: integer, first order, 0.31 Hz. It removes the electrode offset before
   any float math, and its value is the per-channel **raw DC** reported once per second.
2. **Anti-alias FIR**: 127-tap Kaiser (β 5.65, cutoff 925 Hz), evaluated on every second
   input. Error < 0.0073 dB to 850 Hz, ≥ 62.7 dB rejection from 1 kHz, 15.75 ms delay
   (`emg_delay_s` in the .npz meta).
3. **High-pass**: 4th-order Butterworth at 20 Hz (`hp 40` for 40 Hz), two float32 DF2T
   biquads. Rounding error is 2 nV rms.
4. **Scaling**: × 0.25 µV/count with saturation (±8.19 mV). Clips set `PF_CLIP` and the diag
   `clip` mask. Raw codes within 5 % of full scale set the diag `rail` mask (16-bit HP data
   cannot show offset headroom, so watch `dc` and `rail`).

The cost is ~1.2 M MAC/s, estimated at roughly 10-15 % of the 64 MHz M4F (not measured).
`fmt 24` streams the raw ADS codes (no filtering) at `rate` 4000 or 2000. Use it for
bring-up and for checking the filtered path.

## BLE

Advertising name `neurband`, 128-bit service UUID in the advertising data, 200-250 ms
interval. On connect the band asks for 2M PHY, 251-byte data length, MTU 247, and a 7.5-15 ms
connection interval with latency 0. It reports what the link actually got
(`mtu= phy= dle= ci=` in the status). A central that refuses these still works, only slower.

| characteristic | UUID | properties | content |
|---|---|---|---|
| service | `4e420c00-6e65-7572-6261-6e6420726576` | | |
| data | `4e420c01-…` | notify | packets below, one per notification |
| control | `4e420c02-…` | write, write w/o response | ASCII command |
| status | `4e420c03-…` | read, notify | `key=value …` ASCII, refreshed after every command and every 5 s |

Commands: `start`, `stop`, `fmt 16|24`, `rate 2000|4000` (raw stream only; fmt 16 always
acquires at 4 kSPS), `gain 1|2|3|4|6|8|12`, `hp 20|40`, `test on|off`, `short on|off`,
`leadoff on|off`, `rld <mask>` (e.g. `rld 0x0F`), `status`, `off` (System OFF). Settings
changes stop, reconfigure and resume a running stream. Status example:

```
fw=c0.1 st=stream chg=0 vbat=3912 low=0 ads=0x92 verr=0 fmt=16 rate=4000 out=2000 gain=6 hp=20
mux=normal loff=0 rld=0x0f/0x0f imu=1 mtu=247 phy=2M dle=251 ci=7.50 ovr=0 drop=0 serr=0 last=ok:start
```

## Packet format (data characteristic)

Little-endian, packed. Defined in `firmware_c/src/packet.h` and parsed by
`host/neurband_ble.py`. There is no CRC: the BLE link layer already has one, and loss shows
up as `seq` gaps.

| offset | type | field | notes |
|---|---|---|---|
| 0 | u16 | seq | +1 per packet of any type (also for packets dropped in firmware); wraps |
| 2 | u32 | sample | index of the first sample, in units of the stream's output rate; counts lost frames too |
| 6 | u8 | type | 0 = int16 filtered, 1 = int24 raw, 2 = diag, 3 = IMU |
| 7 | u8 | n | samples in this packet (0 for diag) |
| 8 | u8 | flags | b0 marker (button), b1 charging, b2 lead-off on, b3 any lead-off bit, b4 frames lost before this packet, b5 clip/near-rail, b6 battery < 3.5 V, b7 test or shorted inputs |
| 9 | u8 | cfg | b0-3 gain, b4 output rate 4000 (raw only), b5-6 high-pass (0 none, 1 = 20 Hz, 2 = 40 Hz) |
| 10 | u8 | loff_p | OR of LOFF_STATP over the packet (diag: over the last second); bit i = channel i+1 |
| 11 | u8 | loff_n | same, N inputs |
| 12 | … | body | see below |

- **type 0, int16** (default): `n` ≤ 14 samples × 8 channels, sample-major, int16 LE,
  V = count × 0.25 µV. 236 bytes when full.
- **type 1, int24 raw**: `n` ≤ 9 × 8 × 3 bytes, big-endian two's complement exactly as shifted
  out, V = code × 4.8 / gain / 2^24 (47.7 nV at gain 6). 228 bytes when full.
- **type 2, diag** (once per second): `int32 dc[8]` (raw DC, ADS codes), `u8 rail`, `u8 clip`,
  `u8 rld_cfg`, `u8 rld_active`, `u16 vbat_mv`, `u16 overruns`, `u16 drops`,
  `u16 status_err` (44 bytes).
- **type 3, IMU**: `n` ≤ 16 × {u16 dt, i16 gx, gy, gz, ax, ay, az} (14 bytes each). The sample
  index of IMU sample k is `sample + dt_k`, in the same units as the EMG `sample`. The INT1
  interrupt latches the ADS conversion counter, so resolution is 0.5 ms at 2 kSPS output.
  Gyro 17.5 mdps/LSB (±500 dps), accel 0.122 mg/LSB (±4 g), 208 Hz. The IMU runs only while
  streaming. Its registers were written from memory of LSM6DSL DocID028475 section 9; check
  them on the bench (WHO_AM_I must read 0x6A, `imu=1` in the status).

Packets per notification adapt to the negotiated MTU. If the MTU is below 39 bytes, `start`
fails with `err:start`.

## Throughput budget

**Assumptions.** One notification per LL PDU, unencrypted 2M PHY. Each exchange takes
(2+4+2 + 7 L2CAP/ATT + value + 3 CRC) × 4 µs, plus 150 µs, an empty ACK (44 µs) and 150 µs.
That is ~1.36 ms for a 236-byte value. Raw ADC rates for comparison: 2 kSPS × 8 × 24 bit =
384 kbit/s.

| stream | value bytes | notif/s (+IMU 13/s, diag 1/s) | app payload | airtime | per 7.5 ms event | per 15 ms event |
|---|---:|---:|---:|---:|---:|---:|
| **2 kSPS int16 (default)** | 236 | 142.9 (157) | 256 kbit/s + 23 IMU | **21 %** | 1.2 | 2.4 |
| 2 kSPS int24 raw | 228 | 222.2 (236) | 384 kbit/s | 31 % | 1.8 | 3.5 |
| 4 kSPS int24 raw | 228 | 444.4 (458) | 768 kbit/s | 61 % | 3.4 | 6.9 |

Following the stress budget in signal_chain.md section 4 (25 % unavailable events, 20 %
retries), a 7.5 ms interval with ~2 exchanges per event serves ~167 notifications/s. That
covers the default stream with some margin, but neither raw mode reliably. Raw 4 kSPS
needs a central that grants long events (≥ 5 exchanges per event) and a clean channel.
Use it only for short bench captures, and watch `lost_pkts`/`gap_samples`.

Buffering: 20 packets (~140 ms of the default stream) plus a 16 ms frame ring, limited by the
64 KB RAM. Longer radio stalls become counted, visible gaps.

PC centrals: Linux/BlueZ accepts 7.5 ms, and most Intel/Realtek BT 5 adapters take 2M and DLE.
macOS enforces ≥ 15 ms (11.25 ms on some versions). Windows usually settles at 15-30 ms.
`neurband_ble.py` prints the negotiated `mtu/phy/dle/ci`. If `lost_pkts` grows at the
default rate, use the dongle below.

### nRF52840 USB dongle (~$11) as the PC adapter

- **HCI over USB (works with bleak on Linux).** Build Zephyr's `samples/bluetooth/hci_usb` for
  `nrf52840dongle/nrf52840` (NCS: same sample, with the SoftDevice Controller), with
  `CONFIG_BT_CTLR_DATA_LENGTH_MAX=251`, `CONFIG_BT_BUF_ACL_RX_SIZE=251`,
  `CONFIG_BT_BUF_ACL_TX_SIZE=251` and `CONFIG_BT_CTLR_PHY_2M=y`.
  - Flash it through the dongle's USB bootloader (press the sideways RESET button; the red LED
    pulses): `nrfutil pkg generate --hw-version 52 --sd-req=0x00 --application build/zephyr/zephyr.hex --application-version 1 dongle.zip`
    then `nrfutil dfu usb-serial -pkg dongle.zip -p /dev/ttyACM0`.
  - BlueZ shows it as `hci1`. Record with `python3 neurband_ble.py --adapter hci1`. BlueZ uses
    a 30-50 ms connection interval for its own connections; the band then asks for 7.5-15 ms,
    which Linux accepts.
  - For BlueZ's own defaults, `sudo btmgmt --index 1 phy LE1MTX LE1MRX LE2MTX LE2MRX`.
    The recorder tries this, best effort.
  - Windows/macOS cannot easily use a second HCI adapter from bleak.
- **Serial bridge (any OS, not implemented).** A small Zephyr central on the dongle connects
  to the band, enables notifications, and forwards each packet over USB CDC-ACM with a length
  prefix. That takes ~35 kB/s of USB bandwidth, trivial for full-speed USB. The packet format
  above can be passed through unchanged.

## Power budget (estimates, measure on the bench)

All rails come from the XC6206 LDO, so battery current ≈ load current. nRF52832 figures
assume LDO mode (rev C has no DC/DC). Numbers are approximate product-spec values: radio
~10 mA while TX/RX at 0 dBm (5.3 mA is the DC/DC figure); CPU from flash ~7.4 mA when
running.

| block | default stream (2 kSPS int16) | raw 4 kSPS int24 | advertising, idle | System OFF |
|---|---:|---:|---:|---:|
| ADS1298, 8 ch HR (IAVDD 2.75 + IDVDD 0.5 mA at 3 V, datasheet 7.5) | 3.4 mA | 3.4 mA | 3 µA (power-down, 10 µW) | 3 µA |
| nRF52832 radio (airtime × ~10 mA + event overhead) | 2.3 mA | 6.2 mA | ~70 µA | — |
| nRF52832 CPU (DSP ~10-15 %, SPI, BLE host) | 1.1 mA | 0.6 mA | <10 µA | 0.3 µA |
| HFXO, SPIM, TWI, GPIOTE | 0.4 mA | 0.4 mA | — | — |
| LSM6DSL 208 Hz high-performance | ~0.9 mA | ~0.9 mA | 3 µA | 3 µA |
| LED pattern | 0.14 mA | 0.14 mA | 70 µA | 0 |
| LDO Iq + VBAT divider | 3 µA | 3 µA | 3 µA | 3 µA |
| **total** | **≈ 8.2 mA** | **≈ 11.6 mA** | **≈ 0.15 mA** | **≈ 10 µA** |
| 100 mAh cell (~80 mAh usable) | **≈ 10 h** | ≈ 7 h | 5 min, then auto-off | > 6 months (self-discharge dominates) |

Low battery: < 3.5 V shows the LED triple flash and sets `PF_LOWBAT`. At < 3.3 V for three
readings in a row the band stops and enters System OFF. At that point the 3.3 V LDO is in
dropout and AVDD sags.

## LED and button

| LED | meaning |
|---|---|
| 3 quick flashes | boot / wake |
| 1 flash per second | advertising |
| 2 flashes every 2 s | connected, not streaming |
| flash every 0.5 s | streaming |
| triple flash every 2 s | battery < 3.5 V (overrides the above) |
| solid | charging (AFE off, streaming refused) |
| one 0.5 s flash, then dark | entering System OFF |

Button: press = marker (`PF_MARKER` in the next packet, `markers` in the .npz) and resets
the idle timer. Hold 3 s = System OFF; release it, because System OFF waits for the release.
The band also turns off after 5 minutes with no connection and no streaming (`IDLE_OFF_S`
in `main.c`). From System OFF it wakes, as a full reset, on a button press or when a charger
is connected.

## Host recorder

```sh
pip install bleak numpy
cd host
python3 -m unittest -v test_ble_packet               # parser, gaps, IMU, markers, .npz -> analysis.load
python3 neurband_ble.py -o rec.npz                   # default 2 kSPS int16, HP 20 Hz, rld 0x0F
python3 neurband_ble.py --fmt 24 --rate 4000 --duration 10 -o raw.npz
python3 neurband_ble.py --mode short --duration 60   # noise floor
python3 neurband_ble.py --leadoff on --rld 0xff      # contact check with auto-drop of bad senses
python3 -m analysis collect basic --out data/u1 --mark-udp 127.0.0.1:5006   # with software markers
```

It scans for `neurband` (or `--address`), connects, sends the settings, prints `status` and
the negotiated link, enables notifications and sends `start`. Once per second it prints
per-channel RMS (20-450 Hz plus mains notches, the same filter as `neurband_rec.py`), raw
DC, lead-off, rail/clip masks, RLD set, battery, and lost packets/samples. Ctrl-C or
`--duration` sends `stop` and saves.

**Software markers.** `neurband_ble.py` listens on UDP `127.0.0.1:5006` (`--mark-udp`) for the
`MARK <label>` datagrams that `analysis.collect --mark-udp` sends. It maps the host receive
time to a device sample index using the least-delayed packet of the last 5 s. The error is
roughly the minimum BLE latency, ~1 connection interval (≈ 10 ms). These markers are
merged into `markers` together with button presses; `marker_src` tells them apart
(0 = button, 1 = software) and `marker_label` holds the label.

.npz keys. They match `neurband_rec.py`, so `analysis.recording.load` reads them unchanged
with 8 channels.

| key | shape / type | meaning |
|---|---|---|
| `emg` | [N,8] float32 | volts at the electrodes (int16 stream: high-passed; raw: as converted) |
| `t` | [N] float64 | device clock, s from the first sample, = (sample_index − first) / rate. Jumps over gaps |
| `sample_index`, `gain` | [N] | device sample index (output rate) and gain per sample |
| `markers`, `marker_t`, `marker_src`, `marker_label` | [K] | row index into `emg`, time, 0 button / 1 software, label |
| `pkt_seq`, `pkt_sample`, `pkt_flags`, `loff_p`, `loff_n`, `pkt_t_us` | per data packet | header fields; `pkt_t_us` is the device time of the first sample |
| `pkt_rx_mono_ns`, `pkt_rx_wall` | per data packet | host receive time (`time.monotonic_ns()`, `time.time()`) |
| `diag_*` | per second | `diag_dc` [K,8] volts raw DC, `diag_loff_p/n`, `diag_rail`, `diag_clip`, `diag_rld_active`, `diag_vbat_mv`, `diag_sample`, `diag_t`, `diag_rx_mono_ns` |
| `imu`, `imu_sample`, `imu_t` | [M,6] float32, [M] | ax, ay, az (g), gx, gy, gz (deg/s); index/time on the EMG clock |
| `meta` | JSON | rate, gain, vref, lsb_volts, n_channels 8, lost_packets, missed_samples, fw_drops, firmware, link (mtu/phy/dle/ci), status at start/end, fmt, emg_delay_s (0.01575 for int16: FIR delay), imu scales, started / started_host / started_mono_ns |

## Bring-up checklist

Stop at the first failure. Steps 1-7 are bench steps: band **off-body**, powered from a
current-limited supply on the battery pads, SWD attached if needed.

1. **Power.** 3.7-4.0 V on VBAT, 50 mA limit. Check +3V3 and +3V3A (≈ 3.3 V; +3V3A is
   ~30 mV lower under load).
   - Before flashing, PWDN floats with the nRF unprogrammed. There is no pull-down on
     ADC_PWDN; adding a 100 kΩ pull-down is recommended. Expect up to ~4 mA if the ADS wakes.
   - Tens of mA means a short or a part fitted backwards.
2. **SWD.** `pyocd list` sees the CMSIS-DAP probe, and `pyocd commander -t nrf52832` reads
   FICR. If APPROTECT blocks access, erase the chip. Flash the firmware and open `pyocd rtt`.
3. **Crystal.** The RTT log shows `neurband c0.1 up` and BLE advertising starts. A missing
   or wrong 32 MHz crystal stops the BLE stack; an HFXO that fails to start hangs at
   `bt_enable`. The LFRC needs no crystal.
4. **BLE advert.** A phone (nRF Connect app) or `bleak` scan sees `neurband` with the
   service UUID. The LED flashes once per second. RSSI at 1 m should be about −50 to
   −65 dBm; much lower means the antenna match needs tuning (pi pads).
5. **ADS ID.** Connect. The status shows `ads=0x92 verr=0`, and the RTT log shows
   `ADS1298 ID 0x92`.
   - `0x00`/`0xFF`: SPI wiring, CS, mode, or PWDN not high.
   - `verr` > 0: a register did not take.
6. **DRDY / stream.** `python3 neurband_ble.py --fmt 24 --rate 4000 --duration 10`. Scope
   P0.12: 4 kHz falling edges. Check `ovr=0 drop=0 serr=0`, `lost_pkts=0`, and the link
   `phy=2M dle=251 mtu=247`. Then run the default stream for 60 s: zero gaps.
7. **Test signal.** `--fmt 24 --mode test`: all 8 channels show the same ≈1 Hz square wave of
   about VREF/2400 ≈ 1 mV, independent of gain (signal_chain.md section 6 gates). With
   `--fmt 16 --mode test` it becomes high-passed edges (20 Hz HP).
8. **Shorted-input noise.** `--mode short --duration 60`. Datasheet Table 1 (HR, gain 6):
   ~1.1 µVrms at 2 kSPS and 1.5 µVrms at 4 kSPS over the full band. The live 20-450 Hz RMS
   should read ≈1 µV per channel. Repeat with the IMU and BLE active: radio-induced excess
   must stay ≤ 0.5 µVrms (gate).
9. **IMU.** The status shows `imu=1`. At rest `imu[:, 2]` ≈ ±1 g and the gyro ≈ 0 dps.
   `imu_t` advances at 208 Hz on the EMG clock.
10. **Lead-off and bias.** `--leadoff on --rld 0x0F` with nothing connected: `loff` shows
    P/N/X, and `rld` active drops to 0x00 within 1 s. Connect test loads and the bits clear;
    the channels rejoin after 3 s. Turn lead-off off again for clean recordings.
11. **Charger interlock.** Connect the charger (off-body). The LED goes solid, `chg=1`, a
    running stream stops, and `start` returns `err:start`.
12. **On skin. Battery + BLE only: no charger, no SWD, no cable on any pad.** Default
    stream, gain 6, `rld 0x0F`. Relaxed forearm: a few µVrms per channel and no mains in
    the live RMS. A fist gives tens to hundreds of µV. Keep `diag_dc` well inside
    ±400 mV and `rail=0x00`; drop to gain 4 if needed. Press the button and check the
    marker shows up.

## Known limitations / to verify

- **Not linked or run.** All sources compile against Zephyr v4.4.2, but nothing has been
  linked. Not verified: Zephyr 3.7/NCS builds (version guards for `SPI_DT_SPEC_GET`,
  advertising options, `bt_conn_info` intervals and DC/DC are reasoned, not tested), the
  SoftDevice Controller options in `sdc.conf`, flash/RAM fit (static RAM estimate ~60 of
  64 KB: shrink `PKTQ_N` first if it does not fit) and real CPU load.
- **SPI pad byte.** Commands are sent as 2-byte transfers (opcode + 0x00) to avoid nRF52832
  PAN 58. The ADS1298 is assumed to ignore the 0x00 pad, as it does for DIN held low.
  Check on the scope or logic analyser.
- **Interlock edge cases.** CHG_N uses the internal pull-up (~13 kΩ). With no charger, the
  unpowered TP4054 might back-feed through CHRG. Check that CHG_N reads high on battery and
  measure the System OFF current (target ~10 µA).
- **Power-on PWDN.** ADC_PWDN floats while the nRF is in reset (no pull-down), so the ADS
  may run briefly at power-on until the firmware drives it low. That is harmless, but it
  violates the datasheet's "inputs low at power-up" (11.1).
- **IMU.** LSM6DSL register values come from memory of the datasheet (no copy in
  `docs/datasheets/`). Verify CTRL1_XL 0x58, CTRL2_G 0x54, CTRL3_C 0x44, INT1_CTRL 0x01,
  DRDY_PULSE_CFG_G 0x80.
- **Software markers vs `analysis.align`.** Software markers have no reaction time.
  `analysis.align.fit_clock` assumes every marker is a button press 0.25 s after its cue.
  To avoid a bias of up to 0.25 s, fit with `marker_src == 0` only, or use rt = 0 for
  `marker_src == 1`.
- The marker is per packet (7 ms resolution in the default stream). The recorder keeps the
  whole session in RAM (~300 MB/h at the default rate: float32 EMG plus int64 indices).
